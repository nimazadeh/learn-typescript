# استودیوی بصری تسلط بر TypeScript

یک استودیوی یادگیری **کاملاً بصری و گام‌به‌گام** برای تسلط بر TypeScript، ساخته‌شده بر اساس
نقشه‌ی راه رسمی [roadmap.sh/typescript](https://roadmap.sh/typescript) — با **HTML، CSS و
JavaScript خالص** و بدون هیچ فریم‌ورکی در سمت مرورگر.

ویژگی‌های کلیدی:

- **۹۳ درس** در **۱۴ فصل** با پوشش ۱:۱ گره‌های نقشه‌ی راه رسمی.
- **حاشیه‌نویسی فرمول‌های موفقیت** در کنار هر درس (۳۲۷ حاشیه از نوع فرمول، روش مطالعه،
  بهترین رویه، تله‌ی رایج و سؤال مصاحبه).
- **آزمایشگاه زنده با کامپایلر واقعی TypeScript 5.9** به‌همراه «Type X-Ray» که تایپ
  استنتاج‌شده‌ی هر عبارت را با نشانگر `// ^?` نشان می‌دهد.
- **تایمر پومودورو سراسری** با مدت دلخواه و زنگ پایانی ملایم.
- برنامه‌ی روزانه بر پایه‌ی **۵ ساعت مطالعه در روز**.
- رابط کاربری فارسی و **راست‌به‌چپ**، با جداسازی کامل کد و اصطلاحات انگلیسی
  (`unicode-bidi: isolate`).

## اجرا

```bash
npm install
npm start          # http://localhost:3000
```

برای محیط پیش‌نمایش، سرور به `0.0.0.0:3000` متصل می‌شود و همه‌ی درخواست‌های اپ با
**مسیر نسبی** انجام می‌شوند (بدون `localhost` در کد سمت مرورگر).

## تایمر پومودورو سراسری

تایمر در **سربرگ** قرار دارد، نه داخل یک نما — پس با جابه‌جایی بین نقشه، درس، آزمایشگاه و
مربی **از بین نمی‌رود** و با `reviveTimer()` پس از تازه‌کردن صفحه هم برمی‌گردد.

- **هر مدتی، نه فقط پیش‌فرض‌ها**: شمارش معکوس از مدت دلخواه (پیش‌فرض‌های ۵ تا ۹۰ دقیقه +
  ورودی آزاد تا سقف ۴ ساعت).
- **شمارش معکوس واقعی**: `۲۵:۰۰ ← ۲۴:۵۹ ← …` با حلقه‌ی پیشرفت بصری.
- **مبتنی بر `endsAt` نه بر شمارنده**: چون زمان پایان مطلق ذخیره می‌شود، تایمر با
  جابه‌جایی بین نماها، پس‌زمینه‌رفتن مرورگر و حتی **رفرش صفحه** دقیق می‌ماند.
- **زنگ پایانی ملایم، نه آزاردهنده**: سه نت سینوسی (G4 → C5 → E5) با اوجِ تدریجی
  ۰.۰۹ ثانیه و محوِ ۱.۴۵ ثانیه و سقف بهره `MAX_GAIN = 0.06`. تکرار خودکار ندارد و
  با یک کلیک **کاملاً قطع (mute)** می‌شود که در `prefs.sound` پایدار می‌ماند.
- **دو نوع تایمر در یک موتور**: تایمر دلخواه کاربر (`kind: 'custom'`) و بلوک مطالعه‌ی مربی
  (`kind: 'block'`). مربی فقط به پایان بلوک‌های خودش واکنش می‌دهد و دقایق مطالعه را
  ثبت می‌کند؛ تایمر دلخواه هرگز آمار را آلوده نمی‌کند.

موتور تایمر در `src/services/timer.js` و تولید صدا در `src/services/audio.js` است.
پیش‌تر مربی تایمر خصوصی خودش را داشت؛ اکنون **یک موتور** وجود دارد و مربی مشترکِ آن است.

## مدل محتوا

- **۹۳ درس** در **۱۴ فصل** — پوشش ۱:۱ با گره‌های نقشه‌ی راه رسمی.
- هر درس: `goal` + ۳ تا ۵ `steps` (با کد قابل اجرا) + ۲ تا ۵ `margins`
  (حاشیه‌نویسی از نوع `formula | method | cleancode | trap | interview`) + یک `quiz` با توضیح +
  یک `lab` (صورت تمرین، کد اولیه و راه‌حل) + در صورت وجود `visual` (کلید دیاگرام).
- **برنامه‌ی روزانه مشتق‌شده است، نه دستی**: `DAILY_MINUTES = 300` (۵ ساعت) در
  `src/data/curriculum/index.js` و `TOTAL_DAYS` / `DAY_OF_LESSON` / `daysPlan()` از
  دقیقه‌ی هر درس محاسبه می‌شوند.
- **روز ۵ ساعته = ۵ بلوک × (۵۰ دقیقه کار عمیق + ۱۰ دقیقه استراحت)** — تنها منبع حقیقت آن
  `STUDY_BLOCKS` در `src/views/coachView.js` است و `WORK_TOTAL` / `BREAK_TOTAL` /
  `BLOCK_TOTAL` از همان‌جا برون‌بری می‌شوند تا اعتبارسنج و مربی هرگز از هم جدا نیفتند.
- **زبان بلوک کد** با `detectLang()` تشخیص داده می‌شود (`ts | js | bash | json`). بلاک‌های
  پیکربندی مثل `tsconfig.json` با رنگ‌آمیزی JSON نمایش داده می‌شوند و **دکمه‌ی «اجرا در
  آزمایشگاه» ندارند**، چون کامپایلر TypeScript روی آن‌ها فقط خطا تولید می‌کند.

## معماری (DRY)

```
server.mjs                 سرور Node: فایل‌های ایستا + POST /api/compile + /api/health
lib/tsEngine.mjs           موتور کامپایلر TypeScript — تنها پیاده‌سازی (سرور و ابزارهای QA)
index.html                 پوسته‌ی اپ (سربرگ، تایمر سراسری، ناوبری، پالت فرمان)
styles/                    tokens · base · layout · components · views
src/core/                  dom (تنها نقطه‌ی ساخت المان) · store · highlight (چندزبانه)
src/services/              compiler (گفت‌وگو با سرور + Worker ایزوله) · timer · audio
src/data/                  roadmapGraph · curriculum/part1..part10 + index · playbook · playground
src/components/            ui · headerTimer · liveLab · diagrams (DSL اعلانی برای نمودارها)
src/views/                 roadmap · lesson · playground · coach · playbook
src/app.js                 مسیریاب، ناوبری، تم، پالت فرمان (Ctrl+K)، احیای تایمر
lib/tsEngine.mjs           تنها پیاده‌سازی موتور کامپایل (سرور و ممیزی‌ها هر دو همین را صدا می‌زنند)
tools/                     لایه‌های کنترل کیفیت (بخش بعدی)
tools/ts-engine.test.mjs   آزمون واحدِ موتور کامپایل با `node:test`
```

سه قاعده‌ی اصلی:

1. **هر داده یک بار تعریف می‌شود.** فصل‌ها، برنامه‌ی روزانه، آمار محتوا، KPIها و بلوک‌های
   مطالعه همگی از یک منبع مشتق می‌شوند و هیچ عددی در نماها تکرار نمی‌شود.
2. **یک موتور، نه دو.** موتور کامپایلر در `lib/tsEngine.mjs` است و هم سرور و هم ممیزی
   محتوا دقیقاً همان را صدا می‌زنند — پس «کدی که تست می‌شود» با «کدی که کاربر اجرا می‌کند»
   یکی است. همین طور برای تایمر و تولید صدا.
3. **داده از نما جداست.** نمونه‌کدهای آزمایشگاه و چالش‌ها در `src/data/playground.js`
   زندگی می‌کنند تا ابزارهای QA بتوانند مستقیماً همان داده را import و کامپایل کنند.

## کنترل کیفیت

شش لایه‌ی مستقل، هرکدام با کد خروج غیرصفر در صورت شکست:

```bash
npm test        # لایه‌های آفلاین و سریع (محتوا، ماژول‌ها، موتور، لینتر، CSS)
npm run audit   # لایه‌هایی که به سرور نیاز دارند (خودکار سرور موقت بالا می‌آورد)
npm run qa      # هر دو، پشت سر هم
```

| اسکریپت | چه می‌کند |
| --- | --- |
| `npm run validate` | یکپارچگی محتوا: پوشش گره↔درس، فصل‌ها، کوییزها، حاشیه‌نویسی‌ها، برنامه‌ی ۵ ساعته، کلیدهای `visual`، منبع هر KPI، زبان بلوک‌های کد |
| `npm run link` | یکپارچگی ماژول‌ها با پارسر و لینکر خودِ Node (`vm.SourceTextModule`) — گرفتن «export وجود ندارد» پیش از رسیدن به مرورگر |
| `npm run test:engine` | **آزمون واحدِ خودِ موتور کامپایل** (۳۳ آزمون با `node:test`): قرارداد خروجی، پاک‌سازی تایپ، کدهای خطا، راهنمای آموزشی، `readableType`، و همه‌ی حالت‌های X-Ray از جمله **آزمون‌های رگرسیون** برای باگِ پاسخِ جعلیِ `any` |
| `npm run lint` | ESLint با قواعد **باگ‌گیر** (نه سلیقه‌ای): `no-undef`، `no-unused-vars`، `no-dupe-keys`، `require-atomic-updates` و… |
| `npm run audit:css` | متغیرهای CSS تعریف‌نشده، قواعد مرده، کلاس‌های بی‌پوسته، انطباق RTL، `prefers-reduced-motion` |
| `npm run audit:content` | **کامپایل واقعی همه‌ی کدهای آموزشی** با `tsc` (۴۹۹ قطعه): گام درس‌ها، `starter` و `solution` آزمایشگاه‌ها، نمونه‌ها و چالش‌ها |
| `npm run audit:a11y` | axe-core روی DOM واقعی هر ۶ نما + ۱۰ بررسی دستیِ مخصوص RTL/فارسی |
| `npm run smoke` | بالا آوردن کامل اپ در jsdom و اجرای **۸۸ سناریوی واقعی** |
| `npm run format` | Prettier برای کد ابزارها و زیرساخت (داده‌ی آموزشی عمداً مستثناست — `.prettierrc.README.md`) |

### ممیزی محتوا چگونه داوری می‌کند

یک بلوک آموزشی معمولاً مثال «❌ غلط» و «✅ درست» را کنار هم می‌گذارد، پس داوری لایه‌بندی است:

| لایه | چه چیزی | قاعده |
| --- | --- | --- |
| L0 | بلوک `bash`/`json` | اصلاً کامپایل نمی‌شود؛ فقط شمرده و گزارش می‌شود |
| L1 | گام درس‌ها | فقط **خطای سینتکسی** = FAIL (خطای معنایی در مثال عمدی طبیعی است) |
| L2 | `starter` آزمایشگاه | باید **تمیز کامپایل شود** — دانشجو همین را اجرا می‌زند |
| L3 | `solution` و نمونه‌ها | یا تمیز، یا «قطعه» (فقط خطای نبودِ context → WARN)، یا «طرح نیمه‌تمام» (فقط سینتکس) |

خطاهای عمدی و دلیل‌دار در `tools/content-allowlist.json` ثبت می‌شوند. اگر قطعه‌ای که در
allowlist است سالم شود، ممیزی **اخطار «ورودی کهنه»** می‌دهد تا فهرست پوسیده نماند.

### تست دود چه چیزی را واقعاً اجرا می‌کند

`npm run smoke` اپ را در یک DOM واقعی بالا می‌آورد و این‌ها را واقعاً اجرا می‌کند:
رندر هر ۹۳ درس، پاسخ به کوییز و پایدارشدن آن در `localStorage`، **کوییز per-lesson** و
بازگردانی وضعیت پاسخ‌داده‌شده، کامپایل با `tsc` واقعی و افزایش KPI `labRuns`، پرسش‌های
`// ^?` در پنل X-Ray، تولید خروجی JS، اجرای کنسول، **چرخه‌ی کامل تایمر پومودورو**
(شروع → شمارش معکوس → زنده‌ماندن پس از جابه‌جایی بین نماها → توقف → ادامه → پایان →
زنگ → قطع صدا → لغو)، پالت فرمان، و در پایان بررسی می‌کند که **هیچ خطای کنسولی** ثبت نشده باشد.

### قواعد X-Ray (`// ^?`) — و چرا «بی‌پاسخ» بهتر از «پاسخ غلط» است

نشانگر `^` باید **دقیقاً زیر یک عبارت** باشد. موتور عمداً در این حالت‌ها **هیچ** نتیجه‌ای
برنمی‌گرداند:

| وضعیت نشانگر | نتیجه | چرا |
| --- | --- | --- |
| زیرِ شناسه یا لیترال | تایپش را می‌گیرد | حالت مطلوب |
| زیرِ فاصله | بی‌پاسخ | عبارتی آنجا نیست |
| بیرون از طولِ خط بالایی | بی‌پاسخ | پرسش «تراز» نیست |
| زیرِ کلیدواژه (`const`، `type`، `let`) | بی‌پاسخ | کلیدواژه «عبارت» نیست و تایپش `any` بی‌معناست |
| زیرِ نشانه (`=`، `;`، `:`) | بی‌پاسخ | همین‌طور |

دو باگ واقعی اینجا پیدا و رفع شد و اکنون **آزمون رگرسیون** دارند:

1. ستونِ نشانگر بی‌صدا به آخرین نویسه‌ی خط *clamp* می‌شد؛ در نتیجه یک پرسشِ کج، پاسخِ
   عبارتی کاملاً بی‌ربط را برمی‌گرداند.
2. وقتی `^` روی فاصله می‌افتاد، `findTokenAt` به گره‌ی «دربرگیرنده» برمی‌گشت و پنل چیزی
   مثل `const m: Minutes = 50 → any` نشان می‌داد — یعنی کلِ یک دستور به‌عنوان «نام».

> دامنه‌ی `isIdentifier` در خودِ TypeScript **کلیدواژه‌ها را هم شامل می‌شود**، پس فیلترکردن
> کلیدواژه‌ها باید صریح انجام شود. این تله در `lib/tsEngine.mjs` مستند شده است.

### نکته درباره‌ی سرعت موتور

`lib/tsEngine.mjs` یک کش برای `SourceFile` پارس‌شده‌ی libهای رسمی TypeScript دارد. بدون آن،
هر کامپایل ~۳۰۰ms فقط صرف پارسِ دوباره‌ی `lib.es5.d.ts` و `lib.dom.d.ts` می‌کرد؛ با آن،
هر کامپایل ~۱۳ms شد (**بیش از ۲۰ برابر سریع‌تر**) — هم برای آزمایشگاه زنده و هم برای
ممیزی ۴۹۹ قطعه‌ی محتوا که به‌جای ۱۹۰ ثانیه در ۸ ثانیه تمام می‌شود.

### قرارداد API سرور

```bash
GET  /api/health   →  { "ok": true, "tsVersion": "5.9.3" }
POST /api/compile  →  بدنه‌ی درخواست: { "code": "<متن TS>", "flags": { … } }
```

> ⚠️ نام فیلدِ کد **`code`** است نه `source`. اگر اشتباه بفرستید، سرور یک برنامه‌ی
> *خالی* کامپایل می‌کند و بی‌صدا `xrays: []` و `diagnostics: []` برمی‌گرداند —
> یعنی شبیهِ «X-Ray خراب است» به‌نظر می‌رسد در حالی که فقط ورودی خالی بوده.

پاسخ، دقیقاً همان خروجی `compileTypeScript` است:

```jsonc
{
  "ok": true,                 // آیا هیچ دیباگ category:"error" نبود
  "jsCode": "\"use strict\";\n…",
  "diagnostics": [            // هر خطا با راهنمای فارسیِ تعبیه‌شده
    { "code": 2322, "category": "error", "line": 2, "column": 7,
      "message": "Type 'string' is not assignable to type 'number'.",
      "coach": { "title": "…", "advice": "…" } }
  ],
  "xrays": [                  // دو جور: گزارش خودکارِ تعریف‌ها + پاسخِ پرسش‌های ^?
    { "kind": "const", "name": "arr", "type": "number[]", "line": 1 },
    { "kind": "query", "name": "arr", "type": "number[]", "line": 1 }
  ],
  "erasedStats": { "tsBytes": 48, "jsBytes": 43, "erasedNodes": 2 },
  "durationMs": 13.4,
  "tsVersion": "5.9.3"
}
```

`flags` یک **وایت‌لیست** است، چون موتور باید محیطی قابل‌پیش‌بینی و یکسان با پنل UI بسازد؛
تنها این چهار پرچم اثر می‌کنند (دقیقاً همان‌هایی که `src/components/liveLab.js` نشان می‌دهد):
`strict` (پیش‌فرض روشن)، `noUncheckedIndexedAccess`، `exactOptionalPropertyTypes`،
`noImplicitOverride` (پیش‌فرض روشن). پرچمِ بیرون از وایت‌لیست نادیده گرفته می‌شود.
