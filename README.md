# استودیوی بصری تسلط بر TypeScript

یک محیط آموزشی **کاملاً بصری و گام‌به‌گام** برای تسلط بر TypeScript، ساخته‌شده بر اساس
نقشه‌ی راه رسمی [roadmap.sh/typescript](https://roadmap.sh/typescript) — با **HTML، CSS و
JavaScript خالص** و بدون هیچ فریمورکی.

موتور کامپایل، **TypeScript واقعی (۵.۹.۳)** است که روی یک سرور محلی کوچک Node اجرا می‌شود؛
بنابراین خطاها، تایپ‌های استنتاجی و خروجی JavaScript دقیقاً همان چیزی است که `tsc` تولید می‌کند.

---

## اجرا

```bash
npm install
npm start          # http://localhost:3000
```

برای محیط پیش‌نمایش، سرور به `0.0.0.0:3000` متصل می‌شود و همه‌ی درخواست‌های اپ با
**مسیر نسبی** انجام می‌شوند (بدون `localhost` در کد سمت مرورگر).

## مدل محتوا

- **۹۳ درس** در **۱۴ فصل** — پوشش ۱:۱ با گره‌های نقشه‌ی راه رسمی.
- هر درس: `goal` + ۳ تا ۵ `steps` (با کد قابل اجرا) + ۲ تا ۵ `margins`
  (حاشیه‌نویسی از نوع `formula | method | cleancode | trap | interview`) + یک `quiz` با توضیح +
  یک `lab` (صورت تمرین، کد اولیه و راه‌حل).
- **برنامه‌ی روزانه مشتق‌شده است، نه دستی**: `DAILY_MINUTES = 300` (۵ ساعت) در
  `src/data/curriculum/index.js` و `TOTAL_DAYS` / `DAY_OF_LESSON` / `daysPlan()` از
  دقیقه‌ی هر درس محاسبه می‌شوند.
- **روز ۵ ساعته = ۵ بلوک × (۵۰ دقیقه کار عمیق + ۱۰ دقیقه استراحت)** — تنها منبع حقیقت آن
  `STUDY_BLOCKS` در `src/views/coachView.js` است.

## معماری (DRY)

```
server.mjs                 سرور Node + موتور کامپایل TypeScript (بدون وابستگی اجرایی)
index.html                 پوسته‌ی اپ (سربرگ، ناوبری، پالت فرمان، پانوشت)
styles/                    tokens · base · layout · components · views
src/core/                  dom (تنها نقطه‌ی ساخت المان) · store (وضعیت + localStorage) · highlight
src/services/compiler.js   گفت‌وگو با سرور + اجرای JS در Worker ایزوله + حالت آفلاین
src/data/                  roadmapGraph · curriculum/part1..part10 + index · playbook
src/components/            ui · liveLab · diagrams (DSL اعلانی برای نمودارها)
src/views/                 roadmap · lesson · playground · coach · playbook
src/app.js                 مسیریاب، ناوبری، تم، پالت فرمان (Ctrl+K)
tools/                     validate-content · link-check · smoke
```

قاعده‌ی اصلی: **هر داده یک بار تعریف می‌شود**. فصل‌ها، برنامه‌ی روزانه، آمار محتوا و
بلوک‌های مطالعه همگی از یک منبع مشتق می‌شوند و هیچ عددی در نماها تکرار نمی‌شود.

## تست‌ها

```bash
npm run validate   # یکپارچگی محتوا: پوشش گره↔درس، فصل‌ها، کوییزها، حاشیه‌نویسی‌ها، برنامه‌ی ۵ ساعته
npm run link       # یکپارچگی ماژول‌ها با پارسر/لینکر خودِ Node (گرفتن «export وجود ندارد»)
npm run smoke      # بالا آوردن کامل اپ در jsdom و تست ۵۲ سناریوی واقعی
npm test           # هر سه مورد پشت سر هم
```

`npm run smoke` اپ را در یک DOM واقعی بالا می‌آورد و این‌ها را واقعاً اجرا می‌کند:
رندر هر ۹۳ درس، پاسخ به کوییز و پایدارشدن آن در `localStorage`، کامپایل با `tsc` واقعی،
پرسش‌های `// ^?` در پنل X-Ray، تولید خروجی JS، اجرای کنسول، تایمر مربی، پالت فرمان و
جابه‌جایی بین همه‌ی نماها — و در پایان بررسی می‌کند که **هیچ خطای کنسولی** ثبت نشده باشد.

## وابستگی‌ها

| بسته | نقش |
| --- | --- |
| `typescript@5.9.3` | موتور کامپایل سمت سرور (نه در اپلیکیشن) |
| `vazirmatn`، `@fontsource-variable/jetbrains-mono` | فقط برای کپی‌شدن فونت‌ها در `assets/fonts` (خودمیزبان) |
| `jsdom` (devDependency) | اجرای تست دود در محیط DOM |

اپلیکیشن سمت مرورگر **هیچ وابستگی خارجی ندارد**؛ فونت‌ها خودمیزبان و همه‌ی درخواست‌ها نسبی‌اند،
پس استودیو به‌صورت آفلاین هم کار می‌کند.
